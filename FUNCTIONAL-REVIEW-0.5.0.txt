OVF UI 0.5.0 — функциональная проверка
Дата: 01.11.2026

Область проверки

Windows x64, настоящий OVF Tool 9.1.1, два тестовых тенанта Cloud Director
с API 39.0. Первый — API refresh token, второй — логин/пароль. Рабочие ВМ
пользователя не изменялись; защищённая рабочая ВМ не выключалась, не экспортировалась,
её настройки и носители не менялись. Для тестов использовались отдельные
каталоги и образы ovfui-qa050-*, крошечный диск без ОС и незагрузочный ISO.

Основные действия проверены мышью через OVF UI. Расширенная матрица повреждений,
оба формата шаблонов и сценарий capture дополнительно выполнены через тот же
JobManager/API/OVF Tool приложения локальными QA-программами. Это не заявление,
что каждый пункт матрицы был отдельно воспроизведён мышью или что проверены
все возможные сочетания конфигураций Cloud Director.

Исправления

1. Проверка назначения перед импортом и захватом шаблона:
   - точный каталог, все его элементы, совпадение имени без учёта регистра
     и с Unicode NFC-нормализацией;
   - дисковая политика, квота, занято и доступно; наследование единственной
     политики по умолчанию выбранного vDC, если каталог его действительно задаёт;
   - известная нехватка блокирует операцию, неизвестный остаток требует отдельного
     подтверждения. Нулевой лимит не выдаётся за бесконечное свободное место;
   - повтор проверки при старте очереди и общий резерв имён/облачной квоты между
     заданиями. Ёмкость нескольких политик не складывается как единый диск;
   - для OVF/OVA учитывается заявленная ёмкость виртуальных дисков, а не только
     размер сжатого архива; для ISO — размер файла;
   - перед извлечением ISO для capture проверяются также каталог и право capture.

2. Локальный диск и несколько экземпляров:
   - OS-блокировка допускает один экземпляр на пользователя, в том числе при
     разных OVF_DOCK_DATA_DIR. После сбоя ОС освобождает блокировку;
   - локальные резервы учитывают выделенные файловой системой блоки своей
     .partial-папки, а не сетевые байты или логический размер sparse-файла;
   - резерв проверяется во время скачивания; неполные данные сохраняются.

3. Длительные API token передачи:
   - фоновое продление access token во время открытых потоков;
   - сериализация refresh и поколение токена защищают от параллельных HTTP 401;
   - безопасное чтение GET/HEAD может повториться после refresh с сохранением Range;
     потоковая запись PUT/POST автоматически не повторяется;
   - transient-сбой OAuth при proactive refresh допускает прежний токен только
     до безопасной границы срока действия. Отзыв, HTTP 401 и постоянный отказ
     запрещают такой fallback;
   - авторизация не передаётся внешнему transfer-host и не попадает в аргументы
     OVF Tool. Подписанные ссылки и секреты маскируются в журналах.

4. Проверка файлов:
   - OVF/OVA: XML, ссылки на диски, повторные File/Disk ID, fileRef, размеры,
     единицы ёмкости, манифест и его полнота, безопасные относительные пути;
   - ISO в OVF/OVA и подключённый CD/DVD с образом отклоняются, пустой привод
     разрешён. Отдельный ISO загружается как Media;
   - ISO9660/UDF: структурные дескрипторы, границы размера, целостность стандартных
     UDF-дескрипторов, полное чтение и SHA-256; незагрузочный ISO допустим;
   - перед импортом OVF/OVA обязателен настоящий ovftool --verifyOnly;
   - исправлен Windows verbatim-префикс \\?\, из-за которого OVF Tool отклонял
     корректные локальные пакеты.

5. Интерфейс и обновления:
   - фиксированные заголовок/действия формы, прокручиваемое тело и объяснение
     недоступности запуска; отчёт проверки пакета тоже прокручивается;
   - единые формы/кнопки, читаемые ошибки в обеих темах, Owner под каталогом;
   - ошибка отдельной ВМ из vApp с несколькими ВМ — модальное окно;
   - каталоги обновляются после завершения/ошибки/отмены изменения, включая retry;
     очистка истории не теряет событие завершения;
   - обновления OVF UI через публичный GitHub Release: owner/repository в настройках,
     startup/полночь/ручная проверка; SemVer и проверка адреса страницы выпуска;
   - установка обновления вручную, Cloud Director токены для GitHub не используются.

Реальные облачные сценарии

Сценарий                                  Первый тенант     Второй тенант
Вход                                      refresh token    пароль (OpenAPI fallback)
Создание отдельного каталога               успешно          успешно
OVA → каталог → скачивание → проверка      успешно          успешно
OVF → каталог → скачивание → проверка      успешно          успешно
ISO → каталог → скачивание → SHA-256       совпал           совпал
Повтор имени ISO                           отклонён         отклонён
Повреждённые файлы                         отклонены        отклонены
Неизменность каталога после отказов         подтверждена     подтверждена
Выключенная QA vApp → шаблон → OVA          успешно          не выполнялось

Негативная матрица включала пустой и случайный ISO, усечённые ISO/OVA,
некорректный XML OVF, отсутствующий диск, неверный хеш манифеста и ссылку на ISO
в OVF. Это ожидаемые отказы до отправки, а не загрузка мусора в рабочий каталог.

Через Windows UI подтверждены создание каталога и круговой обмен ISO в первом
тенанте, импорт OVA и экспорт OVF во втором, показ политики и свободной квоты,
необходимость подтверждения неизвестной квоты, обновление списка после импорта,
блокировка второго экземпляра. При тестировании облако показывало конкретные
дисковые политики. Их внутренние имена удалены из публичного отчёта.

Захват отдельной QA vApp через форму «Через шаблон в каталоге» также выполнен
мышью: шаблон создан, OVA скачан, проверка завершилась успешно. В светлой теме
проверены читаемость основных списков и настроек. GitHub API проверен через UI
на контрольном публичном репозитории emilk/egui: версия и ссылка получены;
контрольный адрес после теста удалён. Это не репозиторий OVF UI.

Автоматические проверки: 70 тестов библиотеки и один тест настоящего дочернего
процесса прошли; один генератор локальных фикстур намеренно игнорируется.
Rustfmt и Clippy всех targets с -D warnings прошли. Четыре теста защиты
локального QA-инструмента очистки также прошли.

Через UI дополнительно подтверждены отказ для пустого ISO и отдельный модальный
диалог при попытке выбрать одну ВМ из многомашинного vApp. Соседняя включённая
ВМ осталась включённой; экспорт не запускался.

Очистка завершена: все созданные тестовые образы, каталоги и отдельная QA vApp
удалены. Удаление выполнялось по записанным UUID с повторной проверкой типа,
имени, каталога и состава выключенной QA vApp, без force. Во втором тенанте
последующий GET возвращал 403 вместо 404; отсутствие точных UUID подтверждено
полными запросами инвентаря и CatalogItem. Финальный инвентарь обоих тенантов
больше не содержит созданных объектов; защищённая рабочая ВМ остаётся POWERED_ON.

При первом запуске матрицы OVA/OVF был найден дефект Windows-путей; после
исправления повторные импорты/экспорты прошли. Один экспорт OVF был остановлен,
когда свободное место C: упало ниже резерва 2 ГиБ. Повтор через UI на D: успешен.

Проверка производительности

Лимит 0 проходит без ожиданий ограничителя. Бинарные потоки не копируются целиком
в память, TCP_NODELAY включён, соединения переиспользуются. OVF Tool получает
1–16 потоков (по умолчанию 4, кроме ISO); доступность параллельности определяет
OVF Tool и сервер. S3 использует до четырёх multipart-частей с ограничением
памяти. Проверка контрольных сумм требует отдельного чтения с диска.

Локальный HTTPS-тест передаёт по 32 МиБ в обе стороны напрямую и через адаптер,
без физического диска. Он выявляет грубые ограничения адаптера, но не измеряет
канал ЦОДа. Облачные тестовые файлы малы: максимальная скорость большого импорта
в этой версии не измерена и не гарантируется. «Диск» — счётчик записи процесса,
а не независимый тест физического накопителя.

Контрольный замер debug-сборки: через адаптер около 163 МиБ/с при скачивании
и 169 МиБ/с при отправке (прямой TLS: 222/211 МиБ/с). Это дополнительный TLS-hop
и синтетический тест без диска; результаты зависят от нагрузки процессора.

Границы и варианты, которые остаются существенными

- API-квота тенанта не раскрывает физически свободное место провайдера. Другой
  клиент может занять квоту или имя после preflight; распределённой атомарной
  блокировки каталога API не даёт. Перезапись отключена, отказ сервера виден.
- Временный Bearer без refresh token нельзя продлить. Отозванный refresh token,
  истёкшая подписанная transfer-ссылка, обрыв сервера или потеря сети могут
  остановить передачу. Повтор начинается заново; произвольный resume не заявлен.
- Короткий TTL, параллельные 401, transient OAuth и отзыв проверяются на TLS-стенде.
  Многочасовой облачный прогон до реального истечения токена не выполнялся.
- ISO-проверка не доказывает загрузку ОС, работу установщика и целостность каждого
  файла внутри файловой системы. Нестандартные UDF-цепочки могут быть отклонены
  с объяснением; универсальная проверка всех существующих ISO не заявлена.
- Извлечение ISO и отключение ВМ меняют облако только после явного подтверждения.
  В этом прогоне пользовательские ВМ не выключались и носители не извлекались;
  защитные ветви проверены на локальном API-стенде.
- Успех capture не удаляет шаблон. Повтор скачивает созданный шаблон, если он уже
  известен заданию; при неопределённом результате сначала проверьте каталог.
- Отмена клиента не гарантирует отмену уже принятой сервером задачи. Неполные
  локальные данные и серверный объект могут потребовать ручной проверки.
- Реальный S3, Linux GUI, все масштабы/DPI, все права/провайдеры и аппаратные
  конфигурации в этом Windows-прогоне не проверены. Для S3 есть локальные тесты.
- Старые версии без single-instance защиты необходимо закрыть самостоятельно.
- Источник обновлений по умолчанию — RareMxxx/OVF-UI. До первого опубликованного
  Release отсутствие выпуска показывается явно и не означает актуальность версии.
