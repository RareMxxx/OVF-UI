# OVF UI 0.5.0

- В публичной Windows-сборке пути компьютера разработчика заменяются на `/build/...`; перед упаковкой проверяются EXE и остальные файлы дистрибутива. Пользовательские папки и хранилище учётных данных продолжают определяться во время работы.
- Текущий выпуск ограничен Windows x64; описание проекта ориентировано на MWS Cloud Director. Linux пока не выпускается.
- Публичное согласование версии API отделено от авторизованного адаптера: оно не выдаёт служебный ключ, не создаёт ссылки с правами доступа и не использует облачную сессию. Добавлены проверки анонимных запросов, ошибок, перенаправлений и штатного входа OVF Tool.
- GitHub Actions закреплены по SHA; сборка имеет только `contents: read`, checkout не сохраняет токен в Git-конфигурации.
- Проверка обновлений без входа в GitHub и без доступа к секретам приложения; тесты анонимного GET и проверки ссылок выпуска. Исправлено полное скрытие Bearer/Basic и секретов в кавычках в журналах. Архив сборки формируется в чистой папке, рядом создаётся SHA-256.
- Подготовка первого публичного выпуска: RareMxxx/OVF-UI закреплён как источник обновлений; локальные данные и приватные QA-инструменты исключены из публикации, отчёты обезличены.

- Предварительная проверка каталога, имён всех его элементов, дисковых политик и квот. Повтор проверки перед запуском из очереди; резервы имени и облачного места между заданиями.
- Наследуемая политика выбранного vDC и текущая квота читаются из Query API. Неизвестный остаток требует отдельного подтверждения; известный недостаток блокирует передачу.
- ISO9660/UDF: структурная проверка, усечение и некорректные дескрипторы. OVF/OVA: дисковые ёмкости, fileRef/IDs, полнота манифеста, относительные пути. OVF Tool verifyOnly обязателен перед импортом OVF/OVA.
- Современный вход по паролю с fallback при HTTP 404/405; фоновое обновление API refresh token во время потоковой передачи, сериализация обновлений. Поток PUT не повторяется автоматически.
- Один экземпляр приложения на пользователя, OS-блокировка освобождается после сбоя. Локальные резервы учитывают уже выделенные блоки файлов.
- Проверка обновлений OVF UI по GitHub Releases: фиксированный RareMxxx/OVF-UI, startup/полночь/вручную, отдельные состояния ошибок и новой версии.
- Закреплённые заголовок и действия диалога, причина блокировки запуска, читаемые ошибки, квадратные checkbox и автообновление каталога после передачи.
- Исправлены Windows-пути с префиксом verbatim при передаче OVF Tool. Повтор после успешного capture использует созданный шаблон.

Результаты реальных тестов двух тенантов и границы проверки: `FUNCTIONAL-REVIEW-0.5.0.txt`. Публикация: `docs/GITHUB-RELEASES.md`.

# OVF UI 0.4.0

- Единые размеры и скругления кнопок/полей, контрастная светлая тема, адаптивная сетка каталогов и тонкая прокрутка. Ресурсы ВМ: vCPU, RAM, диски.
- Компактный статус OVF Tool без большой анимации и кнопки ручной проверки в боковой панели; ручная проверка перенесена в настройки.
- Ошибка экспорта ВМ из многомашинного vApp показывается в отдельном модальном окне.
- Скачивание через создание шаблона в выбранном каталоге, ожидание задачи и готовности ресурса. Шаблон остаётся в каталоге. Перезапись и автоматическое удаление отключены.
- Проверка подключённых ISO, явное подтверждение извлечения, повторная проверка носителя/питания и результата. Соседние ВМ не выключаются неявно.
- Пакет с ISO или ссылкой на подключённый CD/DVD отклоняется; пустой привод и отдельная загрузка ISO поддерживаются. Локальная проверка обязательна перед импортом и после экспорта.
- Повторная проверка состава vApp перед стартом из очереди; защита от устаревшего результата проверки другого файла.
- Настройка потоков OVF Tool (1–16, по умолчанию 4), TCP_NODELAY на локальном TLS-прокси, параллельные multipart-части S3 с ограничением памяти.
- Полный перечень проверенных сценариев, ограничений и замечаний по скорости: `FUNCTIONAL-REVIEW-0.4.0.txt`.

Проверки выполнялись локально, без запросов в пользовательский Cloud Director: HTTPS-макет capture/eject, ошибки/задержки задач, локальная модель S3, интерфейс на демонстрационных данных. Поддержка конкретного ЦОДа и максимальная скорость его экспорта требуют отдельного приёмочного прогона.

# OVF UI 0.3.0

- Передача разделена на подготовку, передачу файлов и обработку в Cloud Director. Подготовка показывает процент из Task/Progress; если процент ещё неизвестен, общий индикатор показывает 0,1% и название этапа.
- Общий прогресс резервирует 0–5% для подготовки, 5–95% для файлов, 95–99% для обработки. 100% появляется только после подтверждения завершения. Процент отдельного этапа указан под шкалой.
- После выхода OVF Tool приложение опрашивает связанные задачи. При загрузке дополнительно проверяет созданный шаблон/ISO: готовый статус, отсутствие выполняющихся задач и непереданных файлов. Требуются два последовательных подтверждения готовности. При ошибке, отмене ожидания или тайм-ауте успех не показывается.
- Журнал содержит события задач и имена передаваемых файлов; служебные строки machineOutput с плюсами скрыты. Метрика записи переименована в «Диск».
- Owner размещён под названием каталога, кнопка «+ Тенант» выровнена с тенантами. Общий счётчик включает пользовательские ВМ, vApp, каталоги с Owner и их образы; служебные образы и VDC исключены.
- Проверка OVF Tool на официальной странице Broadcom: при запуске, в полночь по локальному времени ПК (в том числе со свёрнутым окном), вручную по кнопке ↻. Актуальная версия помечается latest, новая — кнопкой +upgrade, открывающей Broadcom. Установка не выполняется автоматически. При ошибке сети latest не показывается.
- Новый диалог очереди с отдельными карточками последовательного и одновременного запуска.

Проверка завершения импорта выполняется на локальном HTTPS-стенде с запаздывающими задачами и готовностью объекта. Запись в пользовательский ЦОД в рамках этой версии не выполняется.

# OVF UI 0.2.0

- Приложение переименовано из OVF Dock в OVF UI. Старый каталог настроек, идентификаторы системного хранилища секретов и формат экспорта сохранены: повторный ввод подключений не нужен.
- Овальные кнопки навигации: контур в обычном состоянии, красный контур при наведении и красная заливка выбранной страницы.
- Компактный статус OVF Tool: версия, цветная точка, OK / OFF.
- Диалоги подключения и передачи с красным заголовком, отдельным крестиком, подложкой и блокировкой фоновых кнопок. Тип входа подписан слева. Формат, место назначения и запас диска разделены на блоки.
- Каталоги без Owner скрыты. Пустые пользовательские каталоги видны в списке. Обновление каталогов доступно прямо в окне загрузки и выполняется при его открытии. Создание ожидает завершения задачи и появления каталога в Query API; новый каталог выбирается автоматически.
- Для ВМ читается выделенный объём из VMRecord и уточняется суммой дисков из VM API, чтобы служебные файлы не искажали размер образа.
- Исправлен отказ входа OVF Tool 9.1.1: запрос `Accept: application/*+xml` получал HTTP 406 от Cloud Director. Адаптер добавляет согласованную версию API, не отправляя дублирующий заголовок Accept.
- В сообщениях передач сохраняются тип ошибки OVF Tool, описание, HTTP-статус и причина от Cloud Director. Секреты и подписанные URL скрываются.
- Ожидание серверной подготовки образа подписано отдельно от передачи данных.

## Проверка

Windows: 20 автоматических тестов, rustfmt и clippy. Проверены настоящий вход по токену, получение OVF-дескриптора и полный экспорт vApp в OVA через OVF Tool 9.1.1 — около 3,5 ГиБ, RESULT SUCCESS. Интерфейс проверен в тёмной и светлой темах, включая вложенное создание каталога. Linux использует общий код; запуск в Linux локально не выполнялся. Загрузка в удалённый каталог и S3 не выполнялась.
