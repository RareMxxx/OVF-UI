OVF UI 0.5.0 — независимая критика интерфейса
Дата: 2026-11-01

Область и достоверность

Проверены исходники src/ui.rs и связанные контракты состояния передач и проверки
обновлений. Рекомендации сопоставлены с первичными руководствами Fluent/W3C,
актуальными обсуждениями egui на GitHub и опытом пользователей на форуме.
Обсуждения не рассматриваются как стандарт качества или доказательство дефектов.

Этот документ не утверждает, что последняя сборка визуально проверена полностью.
Субагент-критик не управлял общей мышью, не входил в ЦОДы и не выполнял операции
с пользовательскими объектами. Ниже отдельно приведены факты, сообщённые главным
агентом по его тестированию через Windows UI.

Главный вывод

Основные препятствия в рабочем сценарии исправлены: действие не теряется при
прокрутке длинной формы; блокировка запуска объяснена; проверка квоты показывает
назначение и неопределённость; списки обновляются после завершения операции.
Формы S3 и архива подключений также приведены к общему виду. Проверка Linux UI
и полного набора масштабов окна ещё не завершена.

Что критиковалось и что исправлено

1. Длинный диалог передачи прокручивался вместе с заголовком и кнопками.
   Сейчас header/footer закреплены, прокручивается тело. Причина недоступности
   запуска находится возле основной кнопки. Основание: Fluent Dialog [1].

2. Проверка назначения была скрыта за фактическим запуском.
   В форме есть отдельная проверка каталога, имени, политики и доступной квоты.
   Известный недостаток блокирует запуск. Неизвестная ёмкость явно обозначена
   и требует отдельного подтверждения; она не выдаётся за успешную проверку.
   Изменение параметров отменяет актуальность результата. Перед выполнением
   задания backend проверяет назначение повторно. Поле ошибки сохраняет форму.
   Подход к понятной локальной обратной связи: Fluent Field [2].

3. Смешивались одинаковая геометрия и одинаковая семантика контролов.
   Овальные кнопки сохраняют общий радиус, checkbox получил отдельный малый радиус,
   чтобы не выглядеть как radio. Карточки используют отдельный токен формы.
   Стандартизация не означает, что все типы компонентов обязаны быть круглыми.
   Основание: Fluent Shapes и Checkbox [3, 4].

4. Один красный цвет применялся и как заливка, и как мелкий текст на тёмном фоне.
   Добавлен более светлый error_color для тёмной темы и цвет ссылок. Основные ошибки,
   заголовки и статус передачи используют его; важные красные кнопки получили
   явно белую подпись. Расчёт по sRGB: белый на RED(211,32,54) = 5,21:1;
   тот же RED на карточке(25,27,33) = 3,30:1; muted(77,87,105) на белом = 7,28:1.
   Для обычного текста ориентир W3C — 4,5:1. Это расчёт отдельных пар цветов,
   а не заявление о соответствии всего native-приложения WCAG [5].
   Дополнительно исправлены найденные при заключительном просмотре исключения,
   перечисленные ниже.

5. После загрузки новый образ не появлялся без ручного обновления.
   UI отслеживает новые финальные состояния, объединяет запросы обновления,
   использует tenant_id из JobSnapshot, включая повтор операции. История при
   запуске не вызывает обновления. При открытых формах запрос/применение результата
   откладываются. Очистка истории атомарно возвращает удалённые snapshots:
   завершение между последним кадром и очисткой не теряется.

6. Обновление приложения могло смешиваться с версией OVF Tool.
   Для OVF UI добавлена отдельная карточка GitHub, сохранённый owner/repository,
   понятные ошибки и ссылка на стабильный выпуск. Настраиваемый адрес имеет
   отдельный черновик, поэтому сохранение других настроек его не фиксирует.
   Startup-проверка и ежедневный запрос работают через runtime; ежедневный запрос
   не ждёт отрисовки свёрнутого окна. URL выпуска проверяется перед открытием.
   Реальный репозиторий не подставлен автоматически.

7. Подготовка vCD и фактическая передача выглядели одинаково.
   В текущем UI разделены названия этапов и общий прогресс. Завершение должно
   соответствовать готовности серверного объекта, а не окончанию отправки байтов.
   Принцип непрерывности прогресса и объяснения этапов поддерживает Fluent [6].
   Успех серверного завершения устанавливается backend, не цветом UI.

Подтверждено главным агентом в Windows UI

- ISO в первом тестовом тенанте: загрузка и обратное скачивание прошли.
- OVA во втором тестовом тенанте: загрузка прошла.
- Проверка назначения показала конкретную дисковую политику,
  доступный объём около 174 ГиБ и требуемый объём 1 МиБ в тестовом сценарии.
- Неизвестная квота требует видимого подтверждения.
- Закреплённые header/footer и причина блокировки работают в форме передачи.
- После завершения загрузки счётчик списка изменился до 5 без ручного обновления.

Это результаты отдельных сценариев, сообщённые главным агентом. Они не доказывают
все варианты разрешений, масштабирования, тенантов и размещения в Cloud Director.

Заключительный просмотр исходного кода

Исправлено (P2). Длинный отчёт проверки пакета выходил за нижнюю границу страницы.
    В validation_page добавлена вертикальная ScrollArea вокруг всей страницы,
    включая report.lines/report.warnings. Большой отчёт доступен прокруткой.
    Исправление проверено по коду; визуальный прогон последней сборки здесь
    не утверждается.

Исправлено (P2). Найдены отдельные прямые RED в мелком тексте тёмной темы.
    В transfer_card текст job.message при Failed и название выбранного каталога
    в catalog_grid переведены на error_color, адаптированный к теме.
    Красная заливка кнопок сохранена. Вспомогательные декоративные элементы
    не считаются проверенными этой локальной правкой.

Исправлено (P3). Формы S3 и импорта/экспорта подключений переведены с прежних
    egui::Window на общий form_dialog: заголовок и крестик, прокручиваемое тело,
    закреплённые Отмена/основное действие. Путь архива и пояснения переносятся.
    Сохранение, чтение и защита секретов не менялись. Общее оформление не означает
    одинаковый состав полей во всех формах.

Снижен риск (P3). Выбор способа скачивания, лимит скорости и настройка потоков
    используют horizontal_wrapped вместо обязательной одной строки.

Оставшаяся визуальная проверка

P3. Необходимо проверить перенос и доступность действий при масштабе 150–200%, длинных именах
    ЦОДа/тенанта, длинных локальных путях и минимальном окне. Это риск по структуре
    кода, а не зафиксированный визуальный дефект последней сборки.

Что ещё проверить перед публичным выпуском

- Linux: обе темы, X11/Wayland, системный выбор файлов и Secret Service.
- Масштабирование 100/150/200%; минимальное и широкое окно.
- Навигация Tab/Shift+Tab, фокус после disabled, работа Enter/Esc и видимый focus.
- Длинные имена, крупный отчёт проверки пакета, много каталогов, длинные ошибки API.
- Раздельно: нехватка квоты, неизвестная квота, дубликат имени, повреждённый пакет,
  сетевой отказ проверки GitHub и реальный новый стабильный Release.
- Повтор передачи после переключения тенанта, очистка истории сразу при завершении,
  завершение при открытой форме, переход через полночь в свёрнутом состоянии.

Источники и их применение

[1] Fluent 2 — Dialog usage
https://fluent2.microsoft.design/components/web/react/core/dialog/usage
Первичное руководство: постоянные header/footer при прокрутке тела диалога,
короткие формы и ограниченное количество действий.

[2] Fluent 2 — Field usage
https://fluent2.microsoft.design/components/web/react/core/field/usage
Первичное руководство: inline validation, понятные сообщения и различение
состояний ошибки, предупреждения и успеха.

[3] Fluent 2 — Shapes
https://fluent2.microsoft.design/shapes/
Первичное руководство: семантика форм и единые radius/stroke tokens.
Числа Fluent не перенесены буквально: овальные кнопки — требование пользователя.

[4] Fluent 2 — Checkbox usage
https://fluent2.microsoft.design/components/web/react/core/checkbox/usage
Первичное руководство: checkbox как независимое подтверждение/выбор,
radio/dropdown — для выбора одной альтернативы.

[5] W3C — Understanding Contrast (Minimum)
https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum
Первичный источник числовых ориентиров контраста; используется как инженерная
проверка цветов, а не сертификация native UI.

[6] Fluent 2 — Progress bar usage
https://fluent2.microsoft.design/components/web/react/core/progressbar/usage
Первичное руководство: измеримый/неопределённый прогресс, смена этапов без
необъяснимого движения шкалы назад.

[7] egui GitHub Discussions — themable app components library
https://github.com/emilk/egui/discussions/8740
Обсуждение от 18 октября 2026: автор представляет набор темизируемых компонентов.
Это пример актуального направления разработки, а не доказательство зрелости
библиотеки. Для OVF UI новая зависимость по этому обсуждению не добавлялась.

[8] egui GitHub Discussions — disabled controls and focus
https://github.com/emilk/egui/discussions/8652
Обсуждение от 1 октября 2026 с сообщением об исправлении: повод включить keyboard
QA. Оно касается egui 0.36.2 и не доказывает тот же дефект в версии OVF UI.

[9] Форум r/rust — Egui in 2025: development experience
https://www.reddit.com/r/rust/comments/1m5fwen
Пользовательский опыт от июля 2025, включая критику стандартной светлой темы.
Использован как сигнал для проверки читаемости, не как нормативное требование.

[10] GitHub — egui-pop, ссылка из обсуждения автора [7]
https://github.com/quazardous/egui-pop
Пример развивающегося подхода к общим темизируемым компонентам. Проект не включён
в зависимости OVF UI; существующие egui-компоненты адаптированы собственными токенами.

Документ фиксирует выводы ревью на указанную дату. Новые изменения и результаты
главного агента следует учитывать отдельно; «проверено полностью» здесь не заявлено.
